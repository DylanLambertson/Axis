# Threat model: Phase 1 residual-risk register (owner and ticket per item)

- **Status:** Draft for review. Phase 1 rows RR-1 to RR-30 refreshed 2026-11-26 against `origin/main` `9b2f0e9`; later rows retain the Phase 2a and 4a revisions. Implementation status is not a gate verdict.
- **Evidence rule:** A merged component is called merged only when `git log origin/main` contains it. A gate remains open unless a merged test covers its full scenario; platform and integration limits are in `threat-model-phase1-unverified-gates.md`.
- **What this is.** Every risk that is accepted, open or deferred for the Phase 1a gate review and for 1b, with the owner (the package or workstream that carries the fix), the ticket, and the gate line. Original scores (R1 to R33, controls file §9) are not repeated; the "Risk" column names the row the item belongs to.
- **Decision authority.** Accepting any item below is the project owner's decision (Dylan Lambertson). "Owner" here means the workstream that must do the work.
- **Ticket column.** An id from `docs/design/daemon-host-plan.md` or `docs/design/composer-runtime.md` is a real row. **"Proposed"** marks follow-up work; **"none"** means no ticket is assigned.
- **Status words:** **Open** or **Open gate** means a control, integration or gate test is missing; **Accepted** records a decided residual; **Deferred** assigns a later phase. A merged component can still leave a gate open.
