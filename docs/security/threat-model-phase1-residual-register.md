# Threat model: Phase 1 residual-risk register (owner and ticket per item)

- **Status:** Draft for review. Refreshed 2026-11-20 against `origin/main` `76575e4`, covering merges since `74cd12e`. Implementation status is not a gate verdict.
- **Evidence rule:** A merged component is called merged only when `git log origin/main` contains it. A gate remains open unless a merged test covers the complete gate scenario; see `threat-model-phase1-unverified-gates.md` for platform and integration limits.
- **What this is.** Every risk that is accepted, open or deferred for the Phase 1a gate review and for 1b, with the owner (the package or workstream that carries the fix), the ticket, and the gate line. Original scores (R1 to R33, controls file §9) are not repeated; the "Risk" column names the row the item belongs to.
- **Decision authority.** Accepting any item below is the project owner's decision (Dylan Lambertson). "Owner" here means the workstream that must do the work.
- **Ticket column.** An id from `docs/design/daemon-host-plan.md` or `docs/design/composer-runtime.md` is a real row. **"Proposed"** means the plan lists follow-up work; **"none"** means no ticket is assigned.
- **Status words:** **Open** or **Open gate** means a control, integration or gate test is missing; **Accepted** records a decided residual; **Deferred** assigns a later phase. A merged component can still leave a gate open.

## 3. How to read the gate review against this register

- A 1a gate line is **ready for review** only when every register item that names it is **Accepted**, **Deferred** or closed. Open items against 1a/L2, L3, L10, L14, L15, L17, L18, L24 and L25 still need integration or platform evidence. B9, H13 and X1c are merged; H13b and H9-hooks remain open.
- The slice (`packages/daemon-host/test/slice/`) is evidence for the daemon half of L7, L8, L10 (kill and recover), L20 and L24 **with the fakes named in the compose doc**. It is not evidence for the process-group contract.
