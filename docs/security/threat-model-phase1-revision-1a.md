# Threat model: Phase 1 revision for the 1a-then-1b order (controls as built)

- **Status:** Draft for review. This is the revision the Phase 1a gate asks for ("the threat model is revised for the new phase order before the gate review", `docs/ROADMAP.md`, ADR 0004 implication 7).
- **Date:** 2026-11-05. **Code baseline:** `origin/main` at `b9411b8` (PR #453). Branches that are not on main are named and tagged **[B]**.
- **Relationship to the earlier files.** `threat-model-phase1.md` (the "model") and `threat-model-phase1-controls.md` (the "controls file") stay as the threat tables, gate numbering, decisions and original risk scores. They were written against designs. This file does three things they do not:
  - it records which controls now exist in code, with the package and the merged PR (section 2);
  - it adds the threats that implementation and review found since 2026-11-02 (section 3);
  - it states what is open, so that the gate reviewer does not read a design claim as a built control (section 4).

  Where this file and the two earlier ones disagree about **status**, this file wins. Where they disagree about a threat's wording or the gate line numbers, the earlier files win. Section 5 lists the earlier text that is now stale.
- **Companions:** `threat-model-phase1-residual-register.md` (owner and ticket per residual risk) and `threat-model-phase1-unverified-gates.md` (gate items that Linux cannot verify).
- **Not re-run.** This file was written from the repository, the package and design documents, and independent review notes of the merged and pending work. The test suites were not re-run for it. Where a claim rests on a document and not on code read for this revision, the row says so.

**Evidence tags.**

- **[M]** built and merged on main; the cited file or package page records the behaviour and its tests.
- **[B]** built on a named branch that is not on main; re-check at merge.
- **[R]** a defect or gap raised by an independent review of a branch or PR; recorded here as a threat, not independently re-verified for this file.
- **[I]** inferred. **[D]** design only, nothing built.
- **Built** means code exists. It does not mean the gate line passes: gate lines need an Electron or Code OSS run for the UI parts (see the unverified-gates file).

## 1. What changed in the phase order

ADR 0004 splits Phase 1 into **1a (agent workspace shell, CLI agents, review and push)** and **1b (composer and brokered agent)**. 1a ships first and 1b reuses its challenge and audit mechanisms. Four consequences for the threat model:

1. **1a is mostly a daemon problem, and the daemon host now exists.** `@axis/daemon-host` (#50 to #445) composes the parts into one process that answers real requests. It is the first thing that can be attacked as a whole, and the headless slice (`packages/daemon-host/test/slice/`, `docs/design/daemon-host-compose.md`) is the first end-to-end evidence. It runs on Linux, in a child process, over a real repository and a bare remote, with **fakes for the pty process, the run snapshotter and main** (compose doc, "Fakes and what replaces them").
2. **The unbuilt 1a pieces are on the trust boundary.** The Axis pty process (design task B9; PTY-6, PTY-7, TB9), the real GIT-SNAP-1 wiring into runs, main's side of the control channel (X1 main seam, **[B]** `feat/daemon-entry`) and the renderer UI beyond the A1 shell are not on main. Nothing in production can reach `ready` today: the overlay entry passes no pty port and `composeDaemonHost` throws `pty_required` (compose doc, "Fails closed without a pty") **[M]**; on the entry branch the exit is code 78 **[B]**.
3. **1b is mostly library code.** `@axis/broker` (#46, #52), `@axis/providers` (#24, #27, #35), `@axis/anthropic` and `@axis/vault` (#31) are on main. The daemon-side composer (`feat/composer-runtime`, ticket C1) is a branch **[B]**; its design is `docs/design/composer-runtime.md` on that branch. Every 1b control in section 2 is therefore "library tested, not yet reachable through the daemon".
4. **New trust boundaries.** Add to TB1 to TB11 of the model:
   - **TB12: supervisor (Electron main, or a test parent) to the daemon host process.** One control channel; identity comes only from attestations signed with a per-spawn key main creates and sends in `init`. The host opens no socket (`docs/design/daemon-host.md` §6, `docs/packages.md` "Principals") **[M]**; the Electron adapter and the supervisor are **[B]**.
   - **TB13: daemon to event subscribers (ticket E1, [B] `feat/events-e1`).** A server push channel that did not exist when the model was written. Section 3, N-8.

## 3. New and changed threats found during implementation

Numbering N-n is local to this file. Each row gives the threat, the control, its state, and the ticket that carries it (full register in the residual-register file).

| ID | Threat | Control and state | Ticket |
|---|---|---|---|
| N-1 | **A finished run forges `merged`.** `finalise {outcome: "merged"}` decides on a base branch that a run can influence in the shared repository: the shared `HEAD`, the manager's metadata file, **replace refs**, **`info/grafts`**, a branch ref moved or deleted with a look-alike `refs/heads/refs/heads/<name>`. The journal then records FINALISED/merged for work the base does not contain. No data is lost (the discard scan and the archive ref still apply), but `merged` is not a trusted claim. | **[B]** `fix/worktrees-trusted-base` (FU-WT-BASE) records the base branch at create (set-once column, journal migration 5) and judges against it, which closes the `HEAD` and metadata vectors. **[R]** Replace refs, grafts and the look-alike ref still forged `merged` at the reviewed head; a fix (`--no-replace-objects`, refuse grafts, exact ref resolution) was requested. Branch-ref moves remain by design until the Phase 3 sandbox. Until then `merged` is not attestable. | FU-WT-BASE; follow-up for the remaining ref writes has **no ticket row** (proposed id `FU-WT-BASE-REF`) |
| N-2 | **A lossy binary name waives other files.** Git names are decoded lossily, so distinct files (invalid bytes, overlong forms, a real U+FFFD) share one display string; an allow-list entry for the string would waive all of them, including unscanned secret content. | **[M]** #443: a name containing U+FFFD stays blocked even if listed in `allowedBinaryPaths`, and the scanner is not told it is allowed (`docs/design/daemon-host-git.md`, P1e). - The phase tags of the controls file §8 stand.
