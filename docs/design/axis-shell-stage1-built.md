*Runtime verification.* All runs used throwaway profiles. The servers bound to `127.0.0.1`. Desktop windows were launched in the background, driven over the Chrome DevTools Protocol and closed afterwards.

- **D8** (packaged desktop, `--log trace`): a first start with `--agents` logged `windowsManager#openAgentsWindow: the Agents window is not available in Axis` and opened one normal window on the given folder. A second-instance `--agents` and a second-instance `--open-url -- axis://agents/new?prompt=hello` each logged the same line, and the app kept exactly one window. Not exercised at runtime: opening the `agent-sessions.code-workspace` file (that would open a visible window) and the Windows jump list.
- **H1** (packaged reh-web server): the workbench response carries `require-trusted-types-for 'script'` and the `trusted-types` policy list ending in `vscode-bootstrapImportMap`. In a headless Chrome walkthrough (load the workbench on a folder, Quick Open a file, open the Settings editor from the Command Palette), a `securitypolicyviolation` listener installed before page load recorded 0 violations, and the console showed no Trusted Types messages. The only console errors were two 404s for `vsda`, which Code OSS does not ship.
- **H3** (packaged reh-web server): `GET /?tkn=…` sets `vscode-tkn=…; Max-Age=604800; SameSite=Lax` over plain HTTP, and adds `Secure` when the server runs with `--axis-tls-terminated`. Direct TLS and the non-loopback startup warning are covered by the unit tests only: binding a non-loopback address was avoided.
- **H4** (packaged desktop, a development extension calling `vscode.env.openExternal`): main refused `file:`, `smb:` and a custom `axis-probe:` scheme, logging only the scheme, and nothing was handed to the OS. **Gap, closed in this branch:** upstream's renderer fallback (`src/vs/workbench/electron-browser/window.ts:877-884`) reacted to a refused `file:` URL by calling `showItemInFolder`, so the file was still revealed in Finder (not opened), and the opener returned `true` to the caller for every refused scheme.
- **H4 follow-up** (`2040`, EL-5): the renderer's default external opener no longer reveals a refused `file:` URL and returns main's result; `OpenerService.open` returns the external opener's result for external targets (`openExternal` option, `http`, `https`, `mailto`, `vsls`) instead of falling through to another opener. The overlay tests `axisOpenerService.test.ts` and `axisOpenExternal.test.ts` cover both. They are Code OSS unit tests; they were not run on Linux (§2.9 Linux run below), and the reveal removal has not been exercised in a running macOS or Windows app.
- **EL-5 prompt** (`2050`): upstream's link-protection prompt (`trustedDomainsValidator.ts`) shows the link as a string, or, for a parsed URI, a form shortened to about 60 characters that keeps only the tail of the query. `2050` makes it show the full URL in both cases. Not exercised at runtime. What is **not** done in this branch: confirmation for links from agent output (EL-5 in the threat model, gate 1a/L28) is part of the Axis UI. Upstream's prompt does not cover it, because it skips `mailto`, trusted domains (`open-vsx.org` is trusted by `1030`), links from a trusted workspace and every non-`http(s)` scheme, so the Axis UI must add its own confirmation before it calls `openExternal`.

*Gallery checks* (S1.1 step; `ms-python.python` is an extension pack; `defaultChatAgent` is the inert stub):

- **Development build: passed.** `--install-extension ms-python.python` installed `ms-python.python` 2026.4.0, `ms-python.debugpy` 2026.6.0 and `ms-python.vscode-python-envs` 1.40.0 from Open VSX. `--uninstall-extension ms-python.python` took the pack path and removed all three (`extensions.json` empty). Neither unguarded `defaultChatAgent` reader failed.
- **Packaged build, default settings: failed.** Every install fails with "Signature verification was not executed". Code OSS does not ship `@vscode/vsce-sign`, so verification never runs, and a built product (`isBuilt`) rejects an extension that has no verification result unless `extensions.verifySignature` is `false` (`extensionManagementService.ts:348-363`). Development builds skip this check, which is why the run above passed.
- **Packaged build, `extensions.verifySignature: false` in the test profile:** the same pack install and pack uninstall passed, with the same three extensions.
- Follow-up (owner decision, threat EXT-3 and signature test step 4): a packaged Axis cannot install from Open VSX until extension signature verification is provided, for example Open VSX `.sigzip` verification, or the default is changed deliberately. `docs/feasibility/extension-compatibility.md` should say that the "installs without signature verification" finding applies to development builds only.

*Builds and artifact checks.* `apply.sh` applied 21 patches, 1 removal, 86 replacements, 11 overlay files and 1 hook (the series later grew to 23 patches and 12 overlay files with `2040`, `2050` and the opener tests). `build.sh` passed (`npm ci` 254 s, compile 58 s). The three packaging targets passed (225 s, 59 s and 128 s). `check-artifacts.sh --notices --expect desktop,reh,reh-web` passed on all three artifacts. The packaged desktop app has no JavaScript under `out/vs/sessions`; 14 `SKILL.md` and 2 SVG resource files remain there, inert without the sessions entry points.
