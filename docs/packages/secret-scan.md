# Axis packages: Secret scanner

Part of the package notes; the package map and the cross-cutting rules are in [docs/packages.md](../packages.md).

## Secret scanner

`@axis/secret-scan` is its own package rather than a folder of `@axis/daemon-host`: `@axis/git-ops` and `@axis/review` both consume the scanner type, `@axis/worktrees` builds its default snapshot scanner from it, and a package with no dependencies is easy to test and to bound. It is structurally a `SecretScanner` of `@axis/git-ops` and does not import it.

- **Mode.** `refuse` (default; any value but `refuse` or `warn` parses as `refuse`) or `warn` (a user setting). The host passes the same value as `scanner` mode and `scanMode`. In `refuse` mode a scan that errors, runs out of time (`deadlineMs`, checked between lines and windows) or exceeds `maxBytes` throws a `SecretScanError` with a fixed message, so git-ops refuses the push. In `warn` mode the same events are findings (`scanner-error`, `scan-incomplete`) that need confirmation.
- **Rules.** private key block header, AWS, GCP, GitHub, GitLab, Slack, Stripe, npm and Anthropic/OpenAI-style keys, JWT, credentials or a token in a URL, connection strings with a password, Bearer and Basic headers (Basic must decode to `user:password`), generic assignments (`secret`, `token`, `password`, `passwd`, `pwd`, `credential` and `<word>_key` or `<word>-key` names (the word starts at a word boundary and is at most 64 characters) such as `HMAC_KEY` and `cache_key`, plus `apikey`, `accessKey` and the like; a bare `key` is not a name; value 16 to 256 characters with a digit and a letter and Shannon entropy of at least 3.5 bits, 3.0 for hex), and file names (`.env`, private key names, keystores, `.netrc`, state files). Binary files are scanned up to `maxBinaryBytes` of added text; beyond it, or for git's own `Binary files differ` and `GIT binary patch` markers, the finding is `binary-unscanned`, except for a path in the push's `allowedBinaryPaths` (exact match, the first 50; git-ops passes it in `ScanMeta.allowedBinaryPaths`), so the allow-list works in `refuse` mode. Any Unicode blank, control character, default-ignorable code point, format character (`\p{Cf}`) or Braille blank between a name and its value, or inside a token, is folded first. The fixed-format rules are also run over each new file name (a token in a name), reporting the rule on the path.
- **Guards.** UUID shaped values, code (by shape, not by any bracket, because generated secrets contain brackets: a name or member chain directly followed by a call, an index or a block, an optional chain `?.name`, an arrow `=>`, a chained `).name`, or a regular expression literal; a value that itself starts with a word and then a bracket, or holds `?.name`, is therefore a documented miss), 40 or 64 digit hex only under a name that says digest by whole words (`sha`, `hash`, `digest`, `commit`, `checksum`, `integrity`, `etag`, `fingerprint`, `rev`, `oid`, split on `_`, `-`, digits and camel case, so `shared` is not `sha`; a name that also has a `key`, `secret`, `token`, `password` or similar word is a secret, so `SHARED_SECRET` and `tokenHash` are reported), values that are paths (a leading `/`, `./`, `../` or `~/` and a lower-case word segment) or long options (`--name`), placeholders (`example`, `${..}`, `<..>`), SCREAMING_SNAKE and dotted identifiers, and lock files (generic rules only) do not match.
- **Encodings looked through.** CRLF, tabs, zero-width and bidi characters inside a token, full-width letters (NFKC), name case, and one level of base64 or hex around a fixed-format credential (reported as `base64-<rule>` or `hex-<rule>`).
- **Out of scope (documented misses).** Two levels of encoding, a token split across lines, hunks or string concatenation, `\x41` or `\u0041` escapes, URL-encoded values, base64 glued to other base64-alphabet characters, key material with no header line, secrets that are plain words or lack a digit, values over 256 characters, a UUID shaped secret (Heroku and Snyk tokens), names the generic rule does not know (`DB_PASS`, `passphrase`, `auth:`, `Authorization: Token`, npmrc `_auth`), Stripe `whsec_`, GitLab `glptt-` and `gldt-`, PuTTY key files, file names such as `.aws/credentials`, `.envrc`, `credentials.json`, `*.pem` and `*.key` (a PEM with its header line is found by content), and anything in a commit that the caller truncated (the caller fails closed on truncation).
- **False positives on real code.** Scanning every tracked file of this repository as new-file patches (892 tracked files at the commit that added this sentence, every file read as UTF-8 text, binary files not marked): before the code guard 13 files were flagged with 6 `generic-secret-assignment` findings (5 were code such as `maxOutputTokens: z.number().int()...` and `token: randomBytes(8).toString('hex')`); with the shape guard 11 files and 3 generic findings, all deliberate test strings (two are the positive password examples of `review3.test.ts`, one is in the worktrees tests). Recall is pinned by tests over generated corpora: Django-style 50 character keys with punctuation and brackets at least 90% (92% measured over 2,000; 96% with the `django-insecure-` prefix) and 20 character symbol passwords at least 75% (80% measured). A guard that rejected any bracket measured 32% and 44% on the first two, so the thresholds guard against that regression. What remains is the deliberate canaries and documentation examples of the audit, review and git-ops tests (11 `url-credentials`, a private key header, a connection string, a Bearer header). On the VS Code source about 215 of 226 generic findings were calls and member access.
- **Decoys.** A match a rule rejects (a getter named `getAccessToken`, a weak URL password, a URL value) is skipped one character on, never past the whole value, so a secret after or inside it is still found. The rejected matches of a scan are counted against `maxRejectedMatches` (2,000,000); at the limit the scan is incomplete (`SecretScanError` `budget` in `refuse`, `scan-incomplete` in `warn`), never a silent pass.
- **Bounds.** Patterns use bounded repetition (blanks at most 64, and longer runs of blanks and invisible characters are folded on the whole line first) and no nested quantifiers, so no match is longer than the 4,096 character window overlap; a line longer than `maxLineLength` is scanned in overlapping windows that always share exactly that overlap, and a `maxLineLength` below 8,192 (twice the overlap) is refused with a `RangeError` by `createSecretScanner` and `scanText`, because a smaller window could let a token straddle two windows unseen with no incompleteness flag; `maxFindings` (100,000) stops the scan (in `warn` mode that adds `scan-incomplete`). A clock that answers NaN counts as a deadline. A `part` other than `patch` is read as plain text. The git-ops default `scanMode` is still `warn` when the host omits it, so the host must pass both values. The tests run 1 MiB hostile lines and a 150,000-match patch.
